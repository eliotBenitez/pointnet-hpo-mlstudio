# Раздел «Артефакты» ML Studio

## Назначение

Дать пользователю единое место для просмотра результатов проекта без терминала:

- `report.md` — сводный отчёт по прогонам;
- `data_summary.md` — описание и статистика доступных данных;
- `.pt` — выбор модели и интерактивное 3D-превью её предсказаний на сцене.

Файловая система остаётся источником истины: приложение только читает существующие артефакты и запускает уже имеющийся инференс.

## Цели

- Добавить в левый рельс отдельный пункт «Артефакты».
- Отображать найденные Markdown-файлы внутри приложения на русском UI, сохраняя содержимое документов.
- Дать понятное состояние, если файл отсутствует или пуст.
- Дать отдельный режим 3D-просмотра `.pt` моделей с выбором модели и сцены.
- Переиспользовать существующий механизм загрузки/инференса моделей и данные `cloud.rs`.
- Не показывать выдуманные метрики и не менять формат артефактов или логов.

## Не входит в первую версию

- Редактор Markdown или сохранение изменений.
- Сравнение нескольких моделей одновременно.
- Построение поверхностей/mesh из облака точек.
- GPU-рендеринг, PBR и полноценный 3D-движок.
- Изменение формата `.pt`, `report.md`, `data_summary.md` или Python-инференса.

## Предлагаемый интерфейс

В левом рельсе появляется пункт «Артефакты». Основная область имеет две рабочие зоны:

1. **Документы**
   - Переключатели «Сводный отчёт» и «Данные».
   - Источник файлов: выбранный каталог прогонов для `report.md` и корень проекта/каталог данных для `data_summary.md` согласно существующей логике генерации.
   - Markdown показывается как read-only документ: заголовки, обычный текст, таблицы, списки и кодовые блоки; неизвестное форматирование не теряется и отображается как текст.
   - Рядом с названием отображается фактический путь и состояние файла.

2. **3D-превью моделей**
   - Выбор модели из доступных `best_model.pt`, `trial_XXXX/best.pt` и импортированных `models/*.pt`.
   - Выбор сцены из доступного набора данных.
   - Запуск/обновление предпросмотра через существующий inference pipeline.
   - Интерактивное облако точек: вращение, приближение, панорамирование; переключение отображения истинных классов и предсказаний.
   - Легенда классов использует существующие цвета ML Studio.
   - При отсутствии модели, сцены, результата или совместимого окружения показывается конкретное русское сообщение, а не пустая панель.

Схематично:

```text
Рельс:  Обзор | Запуск | Прогоны | Тестирование | Артефакты | Настройки

Артефакты
[ Сводный отчёт ] [ Данные ] [ 3D-превью модели ]

Документ / модель                         Сцена
┌──────────────────────────────┐          ┌───────────────┐
│ report.md / data_summary.md  │          │ point cloud   │
│ read-only rendered markdown  │          │ rotate / zoom │
└──────────────────────────────┘          └───────────────┘
```

## Технический подход

- Добавить состояние раздела «Артефакты» в `mlstudio/src/main.rs`.
- Вынести/переиспользовать чтение Markdown из существующих файловых путей; не добавлять сторонний webview.
- Если полноценный Markdown-рендеринг отсутствует в используемом GPUI-стеке, применить небольшой детерминированный read-only renderer для поддерживаемых конструкций и безопасный fallback на моноширинный текст.
- Переиспользовать `cloud.rs` для загрузки/подготовки точек и текущий prediction pipeline из `predict_scene.py`/`data.rs`; не дублировать запуск Python.
- Для «3D» использовать интерактивную перспективную проекцию уже загруженных точек с CPU-рендером, согласованную с текущим preview-кодом. Это визуализация point cloud, а не реконструкция mesh.
- Сохранить текущую вкладку «Тестирование» без удаления её функций; новый раздел даёт быстрый самостоятельный просмотр.
- Добавить unit-тесты для разрешения путей документов, выбора моделей/сцен и безопасного поведения при отсутствии файлов. Визуальное поведение проверить сборкой и ручным запуском приложения.

## Ограничения и критерии приёмки

- Все новые подписи и сообщения — на русском.
- `cargo test` проходит.
- `cargo build --release` проходит.
- При пустом `runs/` приложение не падает и не фабрикует отчёт.
- Открытие отсутствующего `report.md` или `data_summary.md` показывает состояние «файл не найден» с путём.
- Загруженная `.pt` модель не копируется повторно и не меняет существующий каталог `models/` без явного импорта.
- 3D-превью показывает реальную выбранную сцену и результат реального инференса; при ошибке инференса отображается ошибка.
- Существующие вкладки запуска, мониторинга и тестирования продолжают собираться и работать.

## Рассмотренные подходы

1. **Отдельный раздел «Артефакты» — выбранный.** Изолирует просмотр документов и моделей, не перегружает «Тестирование», допускает дальнейшее добавление артефактов.
2. Расширение «Тестирования». Меньше навигационных изменений, но смешивает тестирование модели и чтение документов.
3. Только кнопки в карточке прогона. Меньший объём, но не подходит для произвольных импортированных `.pt` и общих документов.

Выбран первый подход, потому что он лучше соответствует запросу на три самостоятельных способа просмотра и сохраняет существующий рабочий поток.

## Открытые решения исполнителя

- Точное расположение `data_summary.md` определяется существующими генераторами и фактической структурой проекта; UI показывает найденный путь.
- В первой версии одновременно отображается один документ или одна модель/сцена.
- Для больших облаков сохраняется существующее прореживание/лимит точек, чтобы превью оставалось отзывчивым.
