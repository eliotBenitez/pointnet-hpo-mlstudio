## 📦 Данные и метрики

- Размер сцены: **200 тыс. — 1 млн точек**.
- Базовые признаки: `x, y, z`. Дополнительно проверить **HAG** и `is_above_ground`, особенно для грунта и растительности.
- Метки для каждого прогона: целевой класс → **1**, фон → **0**.
- Считать **F1-score, Precision и Recall только для целевого класса**. **mIoU не использовать.**

## ✂️ Нарезка на пространственные блоки

1. Разделить данные на Train/Val **по целым сценам**, до формирования патчей. Патчи одной сцены не должны попасть в обе выборки.
2. В `PatchDataset` случайно выбирать точку-центр и собирать соседние точки **в радиусе или кубе**. Нарезка по индексам не подходит.
3. Цель — **около 16 384 точек на патч**. Если точек мало, увеличивать область; если много, случайно прореживать.
4. Батч — **2–4 патча** (примерно **32–64 тыс. точек за шаг**). Размер батча согласовать с доступной памятью GPU.

## 🎲 Воспроизводимость

Фиксировать один seed, например **42**, для:

- разбиения сцен (`split_scenes`);
- инициализации модели (`torch.manual_seed`);
- выбора центров патчей и случайного прореживания в DataLoader;
- `TPESampler(seed=42)` в Optuna;
- перемешивания данных, если оно используется.

Записывать seed и условия запуска вместе с результатами.

## ⚠️ Общие правила экспериментов

1. **Веса классов:** передавать их в `CrossEntropyLoss`, чтобы преобладание фона не привело к постоянному предсказанию 0. Для ложноотражённых точек и воды это обязательно.
2. **Тривиальный baseline:** сравнивать F1 модели с F1 константного предсказания **1 для всех точек**. Если преимущество модели меньше **5%**, проверить, учится ли сеть.
3. **Снижение LR:** использовать `ReduceLROnPlateau` — ранее переобучение наблюдалось после 4-й эпохи.
4. **Разбиение:** Train/Val делить по сценам, без пересечения патчей одной сцены между выборками.
